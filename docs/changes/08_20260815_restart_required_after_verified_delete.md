# 08 - 删除验证通过后仍需重启 EDA 的会话缓存说明

日期：2026-08-15

## 1. 真机现象

`v0.3.1` 已能够精确删除目标扩展，IndexedDB 删除后验证也通过；但在当前 EDA 会话中，扩展管理器或已注册菜单仍可能继续显示目标扩展。完全退出并重新启动嘉立创 EDA / EasyEDA Pro 后，目标扩展才从界面中消失。

## 2. 原因判断

Doctor 当前删除的是 `extensionsIndex`、`extensionsObjectStorage`、`extensionsUserConfig` 中的持久化记录。EDA 在启动/加载扩展时还会把扩展索引、菜单注册和运行实例等状态保存在当前内存会话中。

公开扩展 API 没有提供“热卸载任意指定扩展”或“强制刷新扩展管理器内存缓存”的稳定接口。因此，不应为了让界面立即消失而继续逆向修改 EDA 内部运行时对象。

## 3. v0.3.2 调整

- 保持原有删除事务和删除后验证逻辑不变；
- 不尝试修改 EDA 未公开的内存扩展注册表；
- `confirm-bridge.js` 兼容层同时接管 Doctor 自己的删除成功提示；
- 删除或孤儿清理验证通过后，明确提示：
  - 持久化记录已经删除；
  - 当前会话仍可能看到扩展不表示删除失败；
  - 必须完全退出并重新启动 EDA 才会从编辑器界面消失；
- Doctor 页面顶部增加同样的“重启生效”说明。

## 4. 安全边界

本次修改仅修正状态表达和用户预期，不扩大写入范围：

- 普通删除仍只写 `extensionsIndex`、`extensionsObjectStorage`、`extensionsUserConfig`；
- 孤儿清理仍只写 `extensionsObjectStorage`、`extensionsUserConfig`；
- `standaloneScript` 永不进入写事务；
- Doctor 自身仍禁止删除；
- 删除后残留必须验证为 0 才能报告成功。

## 5. 结论

当前“删除后需重启才从 EDA UI 消失”属于会话内存缓存生命周期问题，不是持久化删除失败。`v0.3.2` 将这一行为作为明确的产品契约展示，而不是冒险实现未公开的热卸载路径。
